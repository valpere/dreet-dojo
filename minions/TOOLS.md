# TOOLS.md — посіпаки dreet-dojo

Помічники агента для власної роботи. Сервіс від них не залежить; у hooks, CI чи сервіси їх не підключати. Bash + jq, без Python.

- `minions/spec-measure.sh [git-rev] [req-uc|hld ...]` — знімає набори специфікацій з `docs/` на ревізії (за замовчуванням `HEAD`; якщо першим аргументом іде назва набору, береться `HEAD`; `req-uc` = requirements.md + use-cases.md, `hld` = hld.md) у read-only `../context/tumanomir/specs/<дата>-<набір>-<rev12>.md`. Наявний знімок того самого коміту з будь-якою довжиною скороченого хешу використовується повторно, а байти знімка дорівнюють простій конкатенації файлів, тож `spec_hash` стабільний. Усі знімки будуються й перевіряються до першого виміру: невідомий набір, ревізія, якої немає, або відсутній на ній файл дають exit 2 без жодного запису. Далі по черзі запускає `tumanomir measure` з `.tumanomir.yaml` цього каталогу: корпус дописується з дедупом за spec_hash і приладом. JSON, stderr і рядок `runs.tsv` зберігаються в `reports/`, а на екран друкується таблиця verdict / D_pair / CI / кластери / H_norm. Збій одного виміру друкується рядком ERROR і не зупиняє решту. Міряти лише ревізії з `main`: ревізії гілок після squash-merge зникають.
- `minions/pr-land.sh <PR>` — зливає PR після рев'ю. Пропускає лише перевірки в bucket `pass` або `skipping` (або відсутність перевірок). На будь-який інший bucket чи помилку `gh` відмовляє з exit 1. Потім squash-merge з `--delete-branch`, перевірка стану `MERGED`, `main` + `pull --ff-only`, 3 останні коміти й рядок `tumanomir check docs/`. Exit 0 = злито (хвостова інформація best-effort). Рев'ю саме не запускає.
